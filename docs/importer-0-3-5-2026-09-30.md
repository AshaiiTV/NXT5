# NXT5 Importer 0.3.5 — Electron 44.4.5 et actions GitHub — 30 septembre 2026

## Contexte

Dependabot a ouvert deux PR qui touchent la chaîne de l’Importer :

- **#99** : Electron 44.4.3 → 44.4.5 dans `importer-app` ;
- **#98** : cinq actions GitHub (`checkout`, `setup-node`, `upload-artifact`, `download-artifact`, `action-gh-release`) dans `build-importer.yml` et `web-ci.yml`.

Chaque fusion sur `main` qui touche `importer-app/**` ou `build-importer.yml` reconstruit et republie la release « latest » de l’Importer, et la vérification de mise à jour compare les numéros de version. Fusionner les deux PR séparément aurait publié deux binaires différents sous le même numéro 0.3.4. Cette PR les regroupe en une seule version, **0.3.5**, et remplace #98 et #99.

## Échec de `pnpm audit` sur #98

Les jobs « Windows app » et « macOS app » de #98 échouaient à l’étape `pnpm audit --audit-level=moderate` (23 alertes). Parmi elles : « undici vulnerable to Denial of Service via unhandled error in WebSocket permessage-deflate decompression » (GHSA-3wwx-pv8p-q78v). Le paquet en cause est donc **`undici`**, pas `ws` : `undici` 6.28.0, tiré par `electron-builder` → `app-builder-lib` → `@electron/rebuild` → `node-gyp`. Les autres alertes concernaient `brace-expansion` (via `minimatch`) et `fast-uri` (via `ajv`).

La branche de #98 partait de `72d29b5`, c’est-à-dire d’avant la 0.3.4 (#95). Les surcharges de `importer-app/pnpm-workspace.yaml` (`undici@6: ^6.28.1`, `brace-expansion` 1/2/5 et `fast-uri@3`) sont arrivées sur `main` avec la 0.3.4 et corrigent déjà toutes ces alertes. Aucune nouvelle surcharge n’est nécessaire : sur `main` avec Electron 44.4.5, `pnpm audit --audit-level=moderate` ne trouve aucune vulnérabilité (`undici` 6.29.0 pour `node-gyp`, 7.30.0 pour `@electron/get`). Dependabot ne rebase pas une PR de groupe d’actions sur `main` sans demande, d’où l’échec persistant de #98.

## Effet sur la publication de la release

Les notes de version des actions ont été relues pour vérifier que la release « latest » reste identique :

- **`action-gh-release` v3** : passage au moteur Node 24 et corrections d’erreurs ; les entrées utilisées (`tag_name`, `name`, `body`, `make_latest`, `overwrite_files`, `files`) ne changent pas.
- **`upload-artifact` v7** : l’envoi sans archive n’a lieu qu’avec `archive: false`, que le workflow n’utilise pas. Les artefacts restent zippés.
- **`download-artifact` v8** : décompresse toujours les artefacts zippés, chacun dans `release-artifacts/<nom>/`, comme avant ; le motif `release-artifacts/**/*` reste valable. Une empreinte non conforme fait désormais échouer le job au lieu d’afficher un avertissement, ce qui est plus sûr pour une publication.
- **`setup-node` v5 et plus** : peut activer seul un cache de dépendances quand `package.json` déclare npm comme gestionnaire. Le `package.json` racine ne le déclare pas, donc rien ne change aujourd’hui. Par précaution, les jobs de build de l’Importer passent `package-manager-cache: false` pour que les binaires publiés ne dépendent jamais d’un cache. `web-ci.yml` garde son `cache: npm` explicite.
- **`checkout` v6 et plus** : identifiants conservés dans un fichier séparé, sans effet sur ces workflows.
