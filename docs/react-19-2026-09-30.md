# Passage à React 19 — 2026-09-30

Remplace la PR Dependabot #101 (`react`, `react-dom` ^18.3.1 → ^19.3.0, `react-test-renderer` 18.3.1 → 19.3.0), dont le contrôle `verify` échouait.

## Dépendances

- `react` et `react-dom` passent à `^19.3.0`, `react-test-renderer` à `19.3.0` (même version que React : le moteur de rendu de test embarque son propre réconciliateur).
- Le fichier de verrouillage reprend celui de #101. Au moment du changement, le registre npm ne liste pas encore `react-test-renderer@19.3.0` dans ses métadonnées (dernière version annoncée : 19.2.8) alors que l’archive est publiée : `npm ci` fonctionne, un `npm install react-test-renderer@19.3.0` peut échouer temporairement.
- Pas d’autre montée nécessaire : `@vitejs/plugin-react` 5.2.0 et `lucide-react` acceptent React 19 ; le dépôt n’utilise ni `@types/react` (le contrôle TypeScript ne couvre que `netlify/functions`), ni `@testing-library/react`, ni routeur tiers.

## Code applicatif

Aucune modification. Le code source n’utilise aucune API retirée en React 19 : pas de `propTypes`/`defaultProps` sur des fonctions, de refs textuelles, de `ReactDOM.render`/`hydrate`, de `findDOMNode`, de `react-dom/test-utils` ni de contexte historique. L’entrée utilise déjà `createRoot`.

## Tests

Toute la suite utilise `react-test-renderer` ; elle est conservée (déprécié en React 19 mais fonctionnel, il affiche un avertissement). Une migration vers `@testing-library/react` serait un chantier séparé.

Le rendu de test n’a plus de mode « legacy » synchrone : les mises à jour faites dans un même `act` sont regroupées et rendues à sa fin. Trois tests supposaient l’ancien comportement :

| Test | Cause | Correction |
| --- | --- | --- |
| `frontend-async-regressions` — B8 « ignores a response from the previous account » | `act(() => onChange(false))` renvoyait la promesse du handler : React 19 la traite comme un `act` asynchrone non attendu, qui englobait les `act` suivants et retardait les effets. Les 7 autres échecs du fichier en découlaient. | Corps entre accolades pour ne pas renvoyer la promesse. |
| `discord-ui` — « copies the full command and verifies only through bounded reads » | 120 s de minuteries avancées dans un seul `act` : un seul rendu, donc une seule relecture au lieu de 24. | Un `act` par intervalle de 5 s. |
| `import-history-view` — « previews JSON… » | L’état occupé (`true` puis `false`) était regroupé dans un seul `act` et jamais rendu. | L’import final reste en attente pour vérifier `onBusyChange(true)`, puis il est résolu. |

Les assertions sont inchangées ; seule la façon de piloter les rendus s’adapte.
